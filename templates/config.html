Modo de comunicação com o Agente

Define como o BEC envia comandos ao Agente Extrator em cada funcionalidade. O modo Cloudflare Tunnel é direto e rápido (~2s); o modo E-mail é o padrão legado. Em Solicitar Logs e Manutenção PDV, o modo Tunnel muda apenas o envio do pedido — o agente continua devolvendo os resultados por e-mail. Vale só para as lojas de PDV: SERVERS_EP_SP sempre usa e-mail, porque a rede de SP não alcança o relay. Manutenção PDV cobre Parametrização, Verificar e Relatório de Parametrização, Status, Fechar e Reiniciar PDV. Registro de Execução é a trilha de auditoria das funcionalidades que o BEC executa sozinho (Exportar Oracle, Requisição API, MDM) — em modo Tunnel, se o relay estiver fora do ar o registro se perde, pois não há reenvio por e-mail. Atualizar Agente vale apenas para o Agent Extrator — o Server Agent SP sempre usa e-mail. Em modo Tunnel o pacote vai em base64 e o limite cai de 25 MB para 18 MB.

📚 Como configurar o Cloudflare Worker (fazer uma vez, válido para todas as máquinas)
  1. Acesse dash.cloudflare.com → Workers & Pages → Create
  2. Cole o código do arquivo cloudflare_worker/worker.js da pasta do projeto (instruções e endpoints em cloudflare_worker/README.md)
  3. Em Settings → Variables, adicione: TOKEN = <seu token secreto>
  4. Em Settings → Variables → KV Namespace Bindings, crie um namespace chamado bec-relay e vincule com o nome de variável KV
  5. Salve e faça o deploy. Copie a URL gerada (ex: https://bec-relay.usuario.workers.dev)
  6. Cole a URL e o token nos campos acima e salve
  7. No agent.properties do agente, configure:
    pinpad_modo_comunicacao=tunnel
    logs_modo_comunicacao=tunnel
    bec_tunnel_url=https://bec-relay.usuario.workers.dev
    pinpad_tunnel_token=<mesmo token>
    loja=0045   pdv=450
    O par loja/pdv do agente precisa ser igual ao Loja/PDV do BEC acima — é o endereço da fila no relay.
